AskDB Inference Decision Lab

A speed–memory–correctness replay for financial SQL tool decisions

Development evidence, not production accuracy. Six fixed contexts supply schema and metric observations. Two repetitions per context measure timing repeatability, not independent accuracy. Greedy bfloat16 CPU inference; model load and network excluded from generation timing. Both configurations use KV caching. Only CPU thread count changes (one versus four).

How to read the trade-off

A valid JSON action can still select the wrong metric, filter, join grain or output shape. The quality gate runs proposed SELECT statements through AskDB's read-only SQL guard and compares returned rows with independently specified fixture answers. Clarification is scored separately. Cache output agreement tests numerical stability on these contexts only.

See comparison.json, requests.csv, and both raw worker JSON files for every observation, token cap, prompt hash, environment and model revision. No scheduled refresh, concurrent service capacity, cloud deployment or hardware-accelerator result is implied.
